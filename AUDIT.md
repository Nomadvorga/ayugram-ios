## 2026-11-26

Nothing below was compiled or run on a device or simulator; all changes are uncommitted in `/Users/toby/work/ayugram-ios` (`plugins-test`). A static preflight pass is not proof that a plugin works. Totals were re-measured by the lead after the review fixes (B-015); other per-area details are as reported by the agents, not reviewed line by line.

- B-007 — Static corpus meter (`python3 -X utf8 -B -m tools.plugin_inspector preflight-corpus --plugin-dir plugins --top 15`): 485 plugins, pass 9, blocked 476, rejected 0. Blocked per kind: `OPERATION` 425, `CLASS` 404, `DEPENDENCY` 47, `REQUIREMENT` 14, `SDK_MEMBER` 14, `IMPORT` 12, `VERSION_POLICY` 1. History 24 → 39 → 56 → 20 → 9: both falls came from making preflight honest (the `OPERATION` blocker, since 44 earlier passes called SDK functions whose host operation does not exist; then the review's false passes, B-015), not from lost functionality. 47 would pass if the host declared the 19 operations of `Python/protocol-telegram.md` (target only; 66 before the review fixes).
- B-008 — Version policy: Python evaluates Android constraints against the emulated SDK 1.4.6.5 / exteraGram 13.2.2 (`Python/_ayu_policy.py`); 478 of 479 version-constrained plugins are satisfied. The Swift edits that defer to it (`plugin.authorize` branch in `Sources/AyuPluginNativeHost.swift`, removed blocker loop in `Integration/AyuPluginService.swift`) are not compiled and have no Swift test.
- B-009 — Worker threads: plugin threads run as Python threads with bridge calls marshalled onto the serial queue; portable tests only. Open on device: threads running between native jobs, pump callback delivery (a full 64-job queue drops them), up to 2 s latency for a worker's first call after idle, unload with a stuck thread. C-level waits on the queue thread do not serve workers.
- B-010 — Python-local Java classes: 346 classes in 14 provider modules, plus concurrency, Telegram and exteraGram facades. Left out: classes needing host pixels/UI (Bitmap, BitmapFactory, drawables), OS services, `javax.crypto`, reflection proxies/fields, DEX class loading.
- B-011 — Telegram plane: TL model (3028 classes, layer 233), facades and per-operation gating exist in Python; 19 host operations are specified (including `resources.resolve`, which gates `R`) and none is implemented in Swift. TL int/long values are now range-checked. 96 TL classes absent from the scheme use a layout parsed heuristically from Java; only `TL_channels_getMessages` is byte-tested.
- B-012 — Xposed: 277 of 485 plugins call `hook_method*` (369 distinct targets, none in more than 7 plugins); before the review fixes 48 were blocked by that alone with all operations declared (not re-measured). No target mapping exists.
- B-013 — Packages: `.elyx`/`.eaf` inspect/preflight/load exist in Python (21/21 inspectable, 0 pass preflight: `OPERATION` blocks 19, `CLASS` 18, `.pyc` bytecode 3); loading has synthetic tests only and the Swift importer does not call it. Unpacking now streams in 64 KiB chunks with a 32 MiB per-entry cap and `O_EXCL|O_NOFOLLOW`.
- B-014 — Portable suites: bridge 606, inspector 71, build 44, all OK. These use a fake host and synthetic sources; they do not establish native API availability.
- B-015 — Review: an independent read-only review found 12 of the 20 then-passing plugins to be false passes. Fixed by gating: package preflight reports `OPERATION` blockers; 21 audited host members (`getWindow`, `getDecorView`, `getDeclaredField`, `addDialogToFolder`, ...) are blocked under the reserved `sdk.unprovided_member`; `R` needs `resources.resolve`; `ChatObject`/`UserObject` need `telegram.peer`; send hooks touching fields beyond peer/message/caption need `telegram.hooks.send_message`; static helpers of `ChatObject`/`UserObject`/`DialogObject`/`MessageObject`/`FileLoader` raise `UnsupportedAPI` for host objects. Remaining weakness: `sdk.unprovided_member` is a curated list, not member-level preflight (that needs `runtime.capabilities` to publish per-class members), so false passes may remain; the 9 passes were audited by member name only.
- B-016 — UI degradations made explicit instead of silent: alert cancel/back listeners raise `UnsupportedAPI`; `make_button_red` is a logged visual degradation (red buttons are not rendered); an `EditText` row with `mask` or `max_length` other than 256 raises.
