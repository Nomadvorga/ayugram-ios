# AyuPluginBridge Python ↔ native protocol v1

## Extensible class adapters (common bridge, first stage)

`AyuBridgeClassRegistry.standard.adding(...)` supplies explicit compiled native
classes to `AyuPluginService`/`AyuPluginNativeHost`. It cannot replace built-in
view, layout, array or proxy classes. Duplicate names, ambiguous members, reserved
reflection names, invalid constants and undeclared writable fields are rejected
when constructing the registry. No Java/JVM, private selector resolution, Java
subclassing or automatic Android API emulation is introduced.

Adapters declare constructors, static/instance methods, explicit read-only dynamic
`staticFields`, constants, readable and
writable fields, and `validateState`. Only declared members are exposed. Hidden
JSON state is not accessible through the private-field helpers. Constructors,
mutations, field writes and factory-created instances all run schema validation,
owned-reference checks and the aggregate `adapterStateBytesPerPlugin` quota
(default 1 MiB). Results additionally obey the response quota. Failed instance
calls roll back state and newly allocated handles. Adapters must be bounded,
side-effect-free synchronous transformations; irreversible app/UI effects belong
in a real application provider, not these closures.

`AyuBridgeAdapterContext` gives typed, read-only snapshots of current-owner
references. It is host-worker-only and generation-scoped; do not retain it or
start threads. Handles/callback tokens remain host-owned. Adapters cannot invent
callback tokens. Atomic classes below provide serial value operations, not plugin
thread support or a Java memory-model guarantee.

`context.callback(reference)` resolves an already registered Python callback on
the host worker and yields a revocable native sender that may be retained by a
native UI action. Sender delivery is asynchronous, generation/ownership checked,
and payload/reference quota validated before reaching the runtime. Never retain
the context itself. `provider.prepareCall` returns `AyuBridgeProviderResult` with
typed value/instance state, `commit(hostOwnedResult)` and `rollback()`: the host
validates and allocates the result before commit, and cancels prepared effects
when validation fails. Providers may not construct wire handles/callback tags.

This file describes the implemented Python API contract. An adapter not explicitly implemented by the host must fail with `UNSUPPORTED_API`; registration or member lookup must never pretend success. This SDK is not a sandbox for untrusted Python. One interpreter and one native-owned serial Python queue are required; threads started by plugin code reach the host only through that queue (see Worker threads). UI effects are enqueued on main; main must never synchronously wait for Python. Native callbacks must return to the Python queue after dispatch returns, never re-enter Python inside `_ayu_host.dispatch`.

## Transport and ownership

Injected extension module: `_ayu_host.dispatch(request_json: str) -> response_json: str`. A request is at most 1,572,864 UTF-8 bytes at this entry point (the SDK and the host apply the per-operation bounds of "Limits and validation" first) and a response at most 1,048,576.

`_ayu_host.wake(plugin_id: str) -> bool` may be called on any Python thread and never blocks. It queues one entry of `service_workers(plugin_id)` on the interpreter thread, with that plugin as the trusted owner, and returns `True` when one is queued or already waiting. Wakes are coalesced to one pending entry per plugin, for at most 32 plugins; `False` means the native queue had no room. It carries no request: the entry only executes bridge calls that the plugin's own worker threads have already queued (see "Worker threads").

Request: `{"version":1,"id":"17","plugin_id":"example","operation":"settings.get","arguments":{"key":"enabled","default":false}}`.

Success: `{"version":1,"id":"17","result":false}`.

Failure: `{"version":1,"id":"17","error":{"code":"UNSUPPORTED_API","message":"Adapter is unavailable"}}`.

Response must contain exactly version/id/result or version/id/error. Unknown fields, duplicate JSON keys, mismatched IDs, nonfinite values and malformed reference tags fail. IDs are decimal strings, correlation only. Host MUST use its externally established trusted owner (native TLS), compare request plugin_id with it, and check ownership/generation on every native handle, token and callback. Request plugin_id is not authority. The host must not leak credentials into errors.

`runtime.capabilities` is requested before code execution with request plugin_id `$runtime`; the host may special-case this read-only bootstrap operation when invoked from a native load with a trusted plugin owner. All other operations require exact owner match. Alternatively return the same capability payload under the trusted owner; the Python implementation currently uses the explicit `$runtime` bootstrap ID.

Wire values: null/bool/string/signed-int64/finite-double, arrays, string-keyed objects. Native reference: `{"$handle":"opaque-id","$class":"declared.class.Name"}`. Python callback: `{"$callback":"opaque-generation-bound-id"}`. Java class reference passed as a value: `{"$java_class":"declared.class.Name"}`. Tags are created by SDK objects only. Host return references must name a declared class. Ordinary dictionaries with reserved `$` keys are rejected by the encoder. No raw pointers, native symbol names, arbitrary selectors or dlsym.

## Native-facing Python entry points (ayu_bridge module)

- `inspect_plugin_json(source, filename="plugin.plugin") -> str`: JSON object containing `metadata`, `imports`, `classes`, `requirements` (`__requirements__` split as Android does, see the metadata policy), `warnings`, `sdk_modules`, `python_stdlib_candidates`, `unsupported_imports`. `sdk_modules` lists this SDK's built-in entry modules. `python_stdlib_candidates` is only CPython's potential stdlib inventory, not evidence that an iOS build ships/supports every entry. `unsupported_imports` maps statically observed disallowed imports to explicit reasons (_thread/multiprocessing/subprocess/ctypes). Host-declared extra dependencies remain opt-in. AST only; no plugin execution and no host calls. `threading` and `concurrent` imports are accepted only when the host declares `scheduler.schedule` and `scheduler.cancel`; otherwise preflight reports them as `IMPORT` blockers and load rejects them.
- `preflight_plugin_json(source, filename="plugin.plugin") -> str`: inspection report plus `blockers` (`code`, `detail`) for missing SDK members, forbidden imports, undeclared dependencies, native classes, missing members of those classes (`MEMBER`, see "Class members"), external requirements and declared operations, and `member_accesses` (`verified`, `guarded`, `missing_accesses`, `unknown`, `unknown_java_style` counts of access sites). Uses host capabilities but never authorizes or executes the source. Computed class names add a warning and remain runtime-checked. Unbundled pip requirements and unmet Android version constraints are `REQUIREMENT` and `VERSION_POLICY` blockers decided by the metadata policy below; the application adds no version rule of its own. Empty blockers are not proof that arbitrary method calls or all stdlib candidates will work on iOS.
- `load_plugin(source, filename="plugin.plugin", expected_id=None) -> dict`: parses literals, verifies expected ID, obtains capabilities, preflights classes/imports/threading, requirements and version constraints, obtains explicit host authorization, then activates the owned host generation, compiles/executes source in a unique module, constructs exactly one BasePlugin subclass, and calls on_plugin_load. Raises BridgeError on failure and revokes partially registered work.
- `unload_plugin(plugin_id) -> bool`: calls on_plugin_unload then always atomically deactivates native scope and drops callbacks/module. on_plugin_unload may call native APIs, but cannot schedule/register new work. Old callbacks are invalid before unload code starts.
- `serialize_settings(plugin_id) -> str`: JSON array of component descriptors. Callback tags in the current generation remain live until unload (or component callbacks are replaced by a later settings serialization).
- `invoke_callback_json(text) -> str`: accepts `{"version":1,"plugin_id":"example","callback_id":"...","arguments":[...]}`. Returns JSON-encoded callback result (not an RPC response envelope). Host must authenticate owner and callback registration before entry. Inactive/unknown callbacks raise CALLBACK_EXPIRED as `DeliveryExpired`, before any plugin code runs; the native runtime answers that with error code 7 instead of the general code 2 (so does `emit_event_json` for a stale generation).
- `service_workers(plugin_id) -> bool`: the entry `_ayu_host.wake` queues. Serves the bridge calls waiting from the worker threads of an active plugin; `False` for a plugin that is not loaded and active. It runs no plugin callback and has no result for the host.
- `emit_event_json(text) -> bool`: accepts `{"version":1,"plugin_id":"example","generation":"<exact load generation>","name":"app","arguments":["RESUME"]}`. Missing/stale generations reject rather than target a newer load. Only app events START/RESUME/PAUSE/STOP are accepted. START is emitted after each successful Python activation; STOP is a background transition, not guaranteed OS termination. Hooks use registered callback IDs instead.

All entry points run on the same queue/thread. WRONG_QUEUE is raised on another thread, including a plugin worker thread. Main interpreter execution is not a security isolation boundary; this layer only scopes bridge state, references and callbacks.

Execution module identity is always the unique `_ayu_plugin_<generation>` name registered in sys.modules. The loader rewrites only the top-level literal `__name__` display-metadata assignment (including annotated/chained assignment targets) to `__ayu_display_name__` in the in-memory AST. Parsed metadata and BasePlugin.name retain the original human-readable title. At runtime `__name__` means Python module identity, not display title; this preserves decorators such as dataclass with forward annotations. No sys.modules alias is registered by display title, so two plugins may share a title safely. Subsequent dynamic mutation of runtime __name__ is unsupported and load-rejected when detected.

## Plugin metadata policy: versions and requirements

Both rules are pure Python in `_ayu_policy.py`, run on parsed metadata literals in preflight and again in `load_plugin` before `plugin.authorize`, and follow exteraGram b4d852f (`PythonPluginsEngine.validatePluginFromFile`, `AppUtils.compareVersions`, `extera_utils.metadata_parser`, `pip/PipController`). Nothing is evaluated by executing plugin code.

Versions. The bridge emulates plugin SDK `1.4.6.5` and exteraGram `13.2.2` (`SDK_VERSION`, `APP_VERSION`). `__min_version__ = "X"` means `app_version >= X` and is ignored when `__app_version__` is present. `__app_version__` and `__sdk_version__` must be `<operator><version>` with operator `>=`, `<=`, `==`, `>` or `<`; the version is trimmed, split on `.`, and compared component by component as signed 32-bit integers with missing components equal to 0 (`1.4` equals `1.4.0.0`, `12.10.06` equals `12.10.6`). Comparison stops at the first differing component, so later components are not validated. A constant is read as `str(value)` and a list as its constants joined by commas. A missing operator, an unparsable reached component, a multi-line value, or a non-constant shape (tuple, dict, nested list) is an invalid constraint. Each unmet or invalid constraint is one `VERSION_POLICY` blocker whose detail states the constraint and the emulated version; `load_plugin` raises `LOAD_REJECTED` with the same text.

Requirements. `__requirements__` is one comma-separated string or a list of constants; a list is joined with commas and split again, and a comma followed by `<`, `>`, `=`, `!`, `~` or `(` continues a version specifier instead of separating. Any other shape, or more than 256 entries, is `LOAD_REJECTED`. Each entry's distribution name is taken as Android's pip controller does (environment marker after `;`, extras and parentheses removed, leading `[A-Za-z0-9_.-]+`, lowercased, runs of `-_.` collapsed to `-`). Nothing is ever installed. A requirement is satisfied only when its distribution is listed in `BUNDLED_DISTRIBUTIONS` and every module it maps to is importable (an SDK module, a module in `capabilities.modules`, or a stdlib name): `requests` (the bundled subset below, when the host declares it) and PyPI backports of stdlib modules (`argparse`, `asyncio`, `contextvars`, `dataclasses`, `enum34`, `ipaddress`, `pathlib`, `statistics`, `typing`). Version specifiers of a bundled distribution are not evaluated, as Android does not evaluate them for its preinstalled packages. A distribution in `PINNED_DISTRIBUTIONS` (the pure-Python packages the app build unpacks from `third-party/ayu-python/packages.lock.json`, see `docs/plugins-python-dependencies.md`) is satisfied only when the host declares its modules and its one pinned version meets every specifier, compared as `PipController.checkVersionSatisfies` does (`==`, `!=` with `.*` wildcards, `>=`, `<=`, `>`, `<`, `~=`, `===`); specifiers of the pinned distributions Android preinstalls (`beautifulsoup4`, `packaging`, `pyyaml`) are not evaluated. Every other requirement is a `REQUIREMENT` blocker whose detail is the normalized distribution name, with a note when the host does not declare the bundled module, when the pinned version does not meet the specifier, or when the package is preinstalled by Android exteraGram only (`debugpy`, `lxml`, `pillow`).

## Scheduling and callbacks

`scheduler.schedule`: `{queue:str,delay_ms:number,callback:{$callback:str}}` → nonempty opaque token string. Queue `main` means schedule a callback back onto the Python serial queue after main scheduling/host prerequisites, NOT execute Python code on main. UI calls made by that callback go to main asynchronously. Other conventional queue names are pluginsQueue/globalQueue/stageQueue/cacheClearQueue/searchQueue/phoneBookQueue/themeQueue/externalNetworkQueue. Host must reject unsupported queues, not run a Python callback on an arbitrary thread. Jobs are one-shot; a callback cannot fire synchronously inside schedule. `scheduler.cancel`: `{token:str}` → null; cancellation must prevent callback entry if it has not begun.

`hooks.register`: `{kind:str,...config}` → opaque token string. Kinds used by SDK: `send_message`, `request` (name,priority), `java_method` (method native ref, before/after callback tags,priority), `java_all_methods` / `java_all_constructors` (class native value, optional name, before/after tags,priority). Unsupported hook kind/target must error before registering. Hook callback receives host-adapted JSON arguments/native refs. `hooks.unregister`: `{token:str}` → null.

`menus.register`: `{type:str,text:str,on_click:callback,...config}` → opaque token.
Only `MESSAGE_CONTEXT_MENU` is wired to the chat message context menu. Supported
optional fields are `item_id` (string), `icon` (one of the native mapped icon
names), `priority` (signed 32-bit integer), and `condition` (Python callback).
`subtext`, `on_long_click`, MVEL condition strings, and other menu types reject
explicitly. A condition and click callback receive one object containing exact
signed-Int64 `account`, `dialog_id`, and `message_id` values; no Java message or
fragment object is constructed. The native provider retains no adapter context,
rechecks callback generation and current chat before dispatch, bounds
registrations/evaluations, and revokes items on unregister or deactivate.
`menus.unregister`: `{token:str}` → null.

Tokens cannot be shared across owners. Host must not invoke retained callback IDs after cancel/deactivate. Python also checks generation and drops one-shot callbacks on invocation.

### Delivery queue

Every host-to-Python delivery (`invoke_callback_json`, `emit_event_json`) passes one bounded queue in front of the interpreter (`Integration/AyuPluginDeliveryQueue.swift`). Nothing waits on main and nothing polls: a delivery is offered to the interpreter when it arrives, when an earlier one completes, and when the runtime reports room after refusing one.

- **Order.** Deliveries of one plugin reach Python in the order their producer handed them over. Plugins take turns, one delivery each. At most 16 deliveries (2 MiB of JSON, or one larger delivery alone) are on the interpreter queue at a time, which leaves its other 48 job slots to load, unload, preflight and settings calls. A delivery the interpreter queue refuses is not an outcome: it keeps its place and is offered again.
- **Bounds per plugin.** 1024 pending deliveries without a producer quota, 256 with one, 8 MiB of pending JSON (24 MiB over all plugins), 6,000,000 bytes for one delivery. A quota-backed delivery of at most 1024 bytes is bounded by its count alone.
- **Unload.** Deliveries still pending for a plugin are discarded when it is unloaded or its load fails; a cancelled timer and a delivery of a revoked generation are discarded when their turn comes. One that is already on the interpreter queue is answered by the interpreter (`CALLBACK_EXPIRED` once the generation is gone).
- **Expiry is not a failure.** A delivery whose callback the plugin released while it waited (a cancelled timer, `Handler.removeCallbacks`, a removed listener), or whose generation was unloaded, runs nothing and is reported nowhere, wherever it was waiting: Android's rule that a cancelled task which has not started never runs. Only an exception from the handler itself marks the plugin's record ("Ошибка обработчика Python").

What happens when a plugin's queue has no room depends on the producer:

| Delivery | Bounded by | No room |
|---|---|---|
| `telegram.request` callback | 64 requests in flight per generation, so a slot always exists | exactly once regardless: when the response bytes do not fit, `(null, error)` with code -1 and text `CALLBACK_QUEUE_FULL` is delivered in its place |
| `scheduler.schedule` timer (`run_on_queue`, `run_on_ui_thread`, `Handler.post*`, `View.post*`, the worker pump) | 128 timers per plugin that are scheduled or have fired but are not yet handed to the interpreter. The slot and the callback id are returned at that hand-over, before the callback runs, so a callback that schedules itself again (the periodic pattern) needs one slot and all 128 can be periodic; at most 16 more are between hand-over and run | never dropped: the 129th `scheduler.schedule` fails with `resource_limit` at the call. `scheduler.cancel` also cancels a timer that fired and has not run, without an error, until the callback starts |
| Lifecycle event (START, RESUME, PAUSE, STOP) | application transitions | queued in order with the quota-backed deliveries; never coalesced |
| Awaited callback: hook answer, menu condition and click, send hook, settings sub-page | the caller | fails at once; the caller continues as for a failed callback (hook strategy 0, hidden menu item, an error in the manager) |
| Listener and notification callbacks (click, text watcher, dialog button, observer), settings `on_change`/`on_click` | nothing | discarded; the plugin's record in the manager states that its callback queue overflowed |
| Subscribed event stream (account events: new message, deletion, file loaded) | nothing: the listener class | as a listener: the event is discarded, never reordered or merged, and the record states the overflow |
| One-shot result of a flow the plugin started (activity result, picker) | one result per started flow, so a slot always exists | exactly once regardless: the small substitute is delivered when the result does not fit |

The native host bounds its own hand-over to this queue at 128 callbacks per plugin; a listener callback past that bound, or one larger than 262,144 bytes of arguments, is reported and flagged the same way. Timers and request callbacks are not subject to it. Nothing is coalesced: no producer today delivers a value that a later delivery supersedes (settings reloads are a native notification, and a generation has at most one pump timer).

A new producer picks one of these classes and does not queue on its own:

- **A stream the plugin subscribed to**, with no bound on how many events the application produces: `AyuBridgeNativeCallback.send(_:)` on the subscription's callback. Events arrive in the order they were sent. The bounds are those of a listener: 128 at the host hand-over, 1024 pending, 262,144 bytes of arguments per event. Past them the event is dropped and the overflow is stated on the plugin's record, so a subscriber sees a gap, never a reordering. A producer that can emit more than 128 events for one plugin in one burst sends them as one event carrying the batch (as Android's `messagesDeleted` carries a list of ids). It must not use the quota-backed call: it holds no quota.
- **One result for something the plugin started**, where the host bounds how many are outstanding (a request in flight, a started activity or picker): `send(_:orOnOverflow:)` with a substitute of at most 1024 encoded bytes that tells the plugin the result was lost, then `release()` for a one-shot callback. It is delivered exactly once.
- **A call whose answer the host needs** (a hook, a condition): `AyuPluginRuntimeRelay.invoke`, which fails at once when there is no room.

## Java facade

`jclass(name)` performs an exact Python-side lookup in capabilities.classes and returns a class facade, or else the Python-local class of that name (below); it does NOT call `java.class` or load a JVM class. Native reflection objects are ordinary owned references returned by supported methods such as getClass/getDeclaredMethod. Arbitrary reflection targets remain unsupported.

Target formats: static class target `{"class_name":"android.view.View"}` or owned object reference `{"$handle":"...","$class":"..."}`. A Java class used in an argument is the separate `$java_class` tag.

| Operation | Exact arguments | Result |
|---|---|---|
| java.member | `{target:target,name:str}` | `{kind:"method"}`, `{kind:"field",value:wireValue}`, or `{kind:"class",class_name:str}`. Missing/unsupported member → error `UNSUPPORTED_API`, never guessed as a method; the SDK raises it as `MissingMember`, an `UnsupportedAPI` that is also an `AttributeError`, so `hasattr` and a `getattr` default see the member as absent |
| java.construct | `{class_name:str,args:[wireValue],kwargs:object}` | owned native reference; adapter may reject overload/kwargs |
| java.invoke | `{target:target,name:str,args:[wireValue],kwargs:object}` | wireValue; supported explicit methods only |
| java.set_field | `{target:target,name:str,value:wireValue}` | null; readonly/unsupported field → error |
| java.length | `{target:objectRef}` | nonnegative int |
| java.get_item | `{target:objectRef,index:int}` | wireValue |
| java.set_item | `{target:objectRef,index:int,value:wireValue}` | null |
| java.array | `{component:str,values:[wireValue]}` | owned array reference with declared class; component is primitive name or declared Java class |
| java.cast | `{class_name:str,value:wireValue}` | type-checked native reference/value; incompatible type → error |
| java.proxy | `{interfaces:[str],callbacks:{methodName:callbackTag}}` | owned listener reference. Interfaces/method names must come from capabilities.proxy_interfaces |

| java.set_private_field | `{target:objectRef,name:str,value:wireValue}` | null, explicitly adapted fields only |

`org.telegram.*`, `android.*`, and `java.*` package imports are provided only if a declared class exists below the package; class access still requires exact registration. Nested classes are returned via `java.member` kind=class, e.g. View.OnClickListener. Native import namespaces may be cached by Python, but class/handle lookup always uses current owner. `jint/jlong/jfloat/jdouble/jboolean/jbyte/jshort/jchar` validate/coerce primitive Python values; arrays are host-owned, not placeholder Python lists. dynamic_proxy only supports explicitly declared interfaces and verifies all required methods when exporting the listener.

### Python-local Java classes

`_ayu_javalib` holds Java classes implemented in Python. `PROVIDER_MODULES` is a fixed tuple of sibling module names; a listed module that is not bundled is skipped, and providers are imported on the first class lookup, never at SDK import. A provider defines `CLASSES: dict[str, type]` keyed by the fully qualified Java name, with `$` for a nested class, which must also be the attribute of its outer class. A provider that breaks these rules, or declares a name another provider declares, raises `ProviderError` on first use.

A class may set `__ayu_requires__ = ("operation.name", ...)`. It is usable only when `capabilities.operations` contains every listed operation; otherwise it stays a `CLASS` blocker and `jclass` raises `UNSUPPORTED_API` naming the missing operation. The SDK derives `capabilities["local_classes"]` from the validated host answer as the usable local names minus `capabilities.classes`: a class the host declares wins, and the host never sees or declares local classes. The one exception is a local class that sets `__ayu_overrides_host__ = True` in its own body: it replaces the host adapter of the same name (used where the adapter implements less than the local class), stays in `local_classes`, and is not submitted to `plugin.authorize`. `plugin.authorize` receives host classes only.

Local names count as declared classes in preflight, in `load_plugin`, and in the native importer, whose package roots are `android`, `androidx`, `org`, `java`, `javax`, `com`, `dalvik`, `kotlin` and `de` (`java` itself stays the SDK module). `runtime.jclass`, `from <package> import Name`, `java.jclass` and `hook_utils.find_class` return the Python class itself. `from java.lang import X` is a class reference, not a member of the SDK module `java`.

Import shapes follow Chaquopy. Its import hook serves `from <package> import <Class>` only, so an import whose module path names a declared class (`import android.graphics.PorterDuff`, `from android.graphics.PorterDuff import Mode`) raises `ModuleNotFoundError` in the native importer, as it raises ImportError on Android; nested classes are reached as attributes of the outer class or with `$` in `jclass`. Preflight reports such an import as `IMPORT` (`<name> (a Java class is not an importable module)`) and `load_plugin` rejects it, unless every occurrence sits in the body of a `try` whose first matching handler (bare, `ImportError`, `ModuleNotFoundError`, `Exception` or `BaseException`) does not re-raise: then the handler runs exactly as on Android and nothing is blocked. The inspection report lists the Java imports outside such a handler in `unguarded_native_imports` (`modules`, `symbols`). `java.chaquopy` is an SDK module with the public surface of `java` (Chaquopy keeps `jclass`, `dynamic_proxy`, `cast` and `jarray` there). Chaquopy functions that need a JVM or DEX (`static_proxy`, `constructor`, `method`, `Override`, `add_class_loader`, `remove_class_loader`, `get_class_loaders`, `unload_class_loader`, `unload_classes`, `set_import_enabled`, `detach`) are not SDK members: importing them is an `SDK_MEMBER` blocker and reading them raises `UNSUPPORTED_API`.

A local object never becomes a host handle. The encoder sends `value.to_bridge()` when the class defines it and otherwise raises `UNSUPPORTED_API`; a local class object passed as a value is refused the same way rather than being registered as a callback. `java.cast` to a local class is an `isinstance` check, `java.jarray` of a local component is a fixed-length Python list, and `dynamic_proxy` over local interfaces yields a plain Python base class; host-declared and local interfaces cannot be mixed in one proxy.

Overriding classes. The host still declares an overridden name, so its own instances keep working: a reference the host returns for that name decodes to an ordinary owned reference served by the Swift adapter, `java.cast(LocalClass, hostObject)` is forwarded to the host's `java.cast`, and the local class object itself (not a subclass) is sent as `{"$java_class": name}`. Local instances cross only as `to_bridge()` data. The overridden adapters are pure statics or value data that no host member takes or returns: `java.lang.Integer`/`Long`/`Short`/`Byte`/`Boolean`/`Float`/`System`, `java.lang.ref.WeakReference`, `java.util.ArrayList`/`HashMap`/`Collections`, `java.util.concurrent.atomic.AtomicLong`/`AtomicBoolean`, `java.net.URL`/`URLEncoder`, `android.graphics.Color`/`Rect`/`RectF`/`Matrix`, `android.os.Bundle`/`SystemClock`/`Handler` and `android.text.InputType`. Names tied to host UI, host-returned objects, proxy interfaces, type-check families or host-owned arrays (`java.lang.String`, `Object`, `Class`, `CharSequence`, `Runnable`, the Spannable/span classes, `TextUtils`, `Typeface`, enums such as `PorterDuff$Mode`, `Locale`, `ByteBuffer`, `ByteArrayOutputStream`, ...) stay host-first.

SDK-served host members. A provider may define `HOST_MEMBERS = {host class name: {member: value}}` for members of a host class that are pure data, yield a Python-local object, or are composed over members the host answers. `Runtime.member` answers them without calling `java.member`: a constant is returned as is, a function is the method, a `HostField(getter)` is a read-only field computed on each read, and a function marked `with_receiver` (as every `HostField` getter) receives the host object or class facade it was read on. `returns(cls)` declares the class a function always returns, for static preflight. A member the host's own table lists for that kind of target (`methods`/`fields` on an object, `static_methods`/`static_fields` on the class) stays the host's, so an adapter that starts to implement a member takes it over. The SDK also answers two members of a host class itself: a nested class `Outer.Inner` whose `Outer$Inner` is a usable Python-local class the host does not declare (`Paint.Align`, `GradientDrawable.Orientation`; such an enum has no wire form and an adapter given one fails with `UNSUPPORTED_API`), and `Class.getClass()` on the class facade (Chaquopy's `Class.class`), which is the host's `java.lang.Class.forName(name)`.

Served today: `android.content.Context` gets the Android `*_SERVICE` name constants and `getSystemService(name)`, which returns the local `ClipboardManager` for `"clipboard"` when that class is usable and raises `UNSUPPORTED_API` for every other service; `MODE_PRIVATE`/`MODE_MULTI_PROCESS`/`MODE_APPEND`; `getPackageName()` (`com.exteragram.messenger`, the application the bridge emulates, as `ApplicationLoader.getApplicationId()`); `getApplicationContext()` (the context itself); `getClassLoader()` (the local `ClassLoader`, whose `loadClass` resolves names through the class registry and throws `ClassNotFoundException` otherwise; it cannot be passed to the host); and the directories below as local `java.io.File`. `android.net.Uri.fromFile(file)` is the host's `Uri.parse` of the encoded `file://` URI. `AndroidUtilities.density` is the host's `dpf2(1)` (Android defines `dpf2(v)` as `density * v`), `AndroidUtilities.displaySize` is the local `Point` of the screen in that unit (the host's display metrics divided by their own density), `UserConfig.clientUserId` is `getClientUserId()`, and `AndroidUtilities.TYPEFACE_*`, `UserConfig.MAX_ACCOUNT_COUNT`, the `MessagesController` masks and filter flags, and the `Intent`, `View`, `MotionEvent`, `HapticFeedbackConstants`, `Gravity`, `ValueAnimator`, `GradientDrawable` and `Paint` constants in `android_content.py`/`android_graphics.py` are Android's values; a constant says nothing about whether an adapter accepts it. `java.nio.ByteBuffer.allocate`/`allocateDirect` return the Python-local buffer (a buffer the plugin allocates is its own memory and cannot be passed to a host member), while `wrap` stays the host's.

Context storage. Every directory is created on demand in the application container and shared by all plugins: `getFilesDir()` and `ApplicationLoader.getFilesDirFixed()` are `Library/Application Support/AyuPluginFiles` (so the plugins directory is its `plugins` child, as on Android), `getCacheDir()` is `Library/Caches/AyuPluginFiles`, `getExternalFilesDir(type)`/`getExternalCacheDir()` are the `external[/type]` children of those two (iOS has no shared storage; `AndroidUtilities.getCacheDir()` is the external cache directory, as Android prefers), `getCodeCacheDir()` is `code_cache` in the cache directory and `getDir(name, MODE_PRIVATE)` is `app_<name>` in the files directory. `getSharedPreferences(name, mode)` returns the local `SharedPreferences` of the calling plugin: one JSON file per name in `shared_prefs/<plugin id>/` of the files directory (at most 1 MiB), never another plugin's file and never the application's, whose own names (`mainconfig`, `userconfing`, `plugin_settings`, ...) raise `UNSUPPORTED_API`. It is not stored through `settings.*`, which is the plugin's settings map (`settings.all` would list it and `settings.replace` would erase it). Values keep their Java type (a getter of another type throws `ClassCastException`), `commit` applies a `clear` first as Android does and returns whether the file was written, `apply` writes before it returns, and listeners are held weakly and called inside `commit`/`apply`, a clear first as a `null` key.

### Class members

`runtime.capabilities` may carry `members`, the table of what each host class provides:

```
"members": {"version": 1, "classes": {"<class name>": {
    "constructor": bool,            // java.construct can succeed for some arguments
    "methods": [str],               // instance methods java.member answers on an object
    "fields": [str],                // readable instance fields
    "writable_fields": [str],       // subset of fields that java.set_field accepts
    "static_methods": [str],        // methods java.member answers on the class target
    "static_fields": [str],         // constants and static fields
    "results": {member: className}  // members whose value or call result is always an instance of that host class, or null
}}}
```

Every key of an entry is required. A class name must be in `classes`; a class without an entry has unknown members. Member names are ASCII identifiers of at most 128 bytes that do not start with `_`, unique within a list; a list holds at most 2,048 names and the table at most 4,096 classes. A `results` key names a member of the entry and its value a class of `classes`. Nested classes are not listed: `Outer.Inner` is a static member of `Outer` exactly when `Outer$Inner` is in `classes`. The SDK rejects a malformed table as `PROTOCOL_ERROR`, ignores a table whose `version` is greater than 1 as a whole, and stores a valid one as `capabilities["members"]` (the `classes` object). A host that sends no `members` key keeps the earlier behaviour: its classes' members are unknown and nothing is blocked for them.

The Swift host builds the table from the registry that serves `java.member`, `java.construct` and `java.set_field` (`AyuPluginNativeHost.classMembers`), so a listed name is one the host answers and an unlisted one is `UNSUPPORTED_API`. It omits the whole table when the names would take more than half of the response quota. `results` comes from `AyuBridgeClassAdapter.results`, an optional declaration the registry validates and the host enforces on every call (another result is `INVALID_ADAPTER`); adapters that declare none publish `{}`. A listed method can still reject an overload or raise for its arguments: the table says a member exists, not that every call succeeds.

Python-local classes need no table. `_ayu_members` reads them from the class objects and the provider sources: the public names of the class, its bases and its metaclass; the instance fields its methods assign (`self.name = ...`, `self.__dict__["name"] = ...`), `__slots__`, and the schema fields of a generated TL class. A member whose definition can only raise is not provided, whatever `hasattr` says: a function whose every path ends in `raise` (unless what it raises is a Java exception class, which is the member's Java behaviour), a descriptor whose `__get__` only raises, and an `__init__` of that kind (no constructor). A class whose `__getattr__` can return, or that fills `__dict__` from data, has unknown members beyond the ones found. A provider whose source cannot be read has unknown members.

Static receiver inference (`_ayu_inspection.member_inventory`) decides, from the AST alone, which class a member access is on. A receiver is resolved when it is: a class bound by `from <java.package> import Class`, `java.jclass("...")` or `hook_utils.find_class("...")` with a literal name; a nested class (`Outer.Inner`); an instance constructed from a resolved class (`Class(...)`); a name, or an attribute of the plugin class's own `self`, whose every binding in its scope yields that one class (`None` assignments aside); a constant of a local class that is itself a local class or instance; and a call or field whose result class is declared: by `results` for a host class, by a Python-local definition all of whose `return`s construct one class or return `self`, or by a `client_utils` controller getter. Parameters, loop and `with` targets, results of any other call, names bound to two classes, an attribute also assigned through another receiver, and classes without a table are unknown receivers: they are counted in `member_accesses.unknown` (`unknown_java_style` counts the camelCase and CONSTANT_CASE names among them) and never produce a blocker. Accesses on classes the host does not declare are left to the `CLASS` blocker.

A member the host adapter lacks but the Python-local class of the same name provides, when that class overrides the adapter and is unusable only because the host does not declare one of its operations (`MessagesController.getInputPeer` without `telegram.peer`), is an `OPERATION` blocker with the detail `<operation> (<class>.<member>)`, not a `MEMBER` one. Any other resolved access to a member that neither the host table nor the local class provides is a `MEMBER` blocker with the detail `<class>.<member>`, `<class>.<member> (write)` for an assignment the class does not accept, or `<class>.<init>` for a class that cannot be constructed; each detail is reported once per source. A probe is not a blocker and is counted in `member_accesses.guarded`: the member name is tested with `hasattr(x, "name")` or `getattr(x, "name", default)` in the same function, or the access is in the body of a `try` whose first matching handler names `AttributeError` and does not re-raise. A blanket `except Exception` or bare `except` is not a probe, because the code behind it would silently never run. `MEMBER` is a preflight blocker only; `load_plugin` does not repeat it and the call itself raises.

The curated list `_ayu_operations.UNPROVIDED_MEMBERS` (reserved operation `sdk.unprovided_member`) stays as the net under unknown receivers: a listed name blocks only when the source uses it on at least one receiver inspection could not resolve. Package preflight (`preflight_package_json`) does not run the member check.

Reflection. `java_reflect` gives `java.lang.Class` its member lookups (`getDeclaredField(s)`, `getField(s)`, `getDeclaredMethod(s)`, `getMethod(s)`) over a model of each class: for a Python-local class the public members of its table above (`to_bridge` excluded), for a host class the names of its published member entry plus its `HOST_MEMBERS`; a host class without an entry has no model and the lookup raises `UNSUPPORTED_API`. A found member is a local `java.lang.reflect.Field` or `Method` that reads, writes or calls the member by name (`Field.get/set`, the typed getters, `Method.invoke`, `setAccessible`, `getDeclaringClass`, `getModifiers`); every modelled member counts as public, `Method.invoke` wraps a Java throwable of the method in `InvocationTargetException`, parameter types select by their count only, and `getParameterTypes`/`getReturnType` exist only where the SDK function declares `__ayu_java_signature__`. A name the model lacks throws `NoSuchFieldException(name)` or `NoSuchMethodException("<class>.<name> [<types>]")`, as Android words them. The lookups are served on the local `Class` mirror (`LocalClass.getClass()`, a primitive's mirror has no members), on a host class facade and on the host's own class object (told from an instance by its `isPrimitive` member); a lookup the host's table lists (`getDeclaredMethod(s)`) stays the host's, and a local class is not its own `Class` object, as in Chaquopy. `Class.forName(name[, initialize, loader])` on the host's `java.lang.Class` returns the local mirror for a usable Python-local class and the host's object otherwise, and throws `ClassNotFoundException` for a name neither knows. Preflight types `getClass()` of a resolved class or instance, then checks a lookup whose name is a string literal against the same model: a member the model lacks is `MEMBER <class>.<name>`. A lookup on a resolved class with any other name, on a class without a model, or on an unresolved receiver keeps the curated `getDeclaredField` blocker (`_ayu_operations.MODELLED_MEMBERS` names the curated members that are provided for modelled classes only).

Constructors. A Python-local class whose constructor refuses some argument values declares `__ayu_constructs__(arguments)` (a static method taking the call's positional arguments where the source spells them as literals, `...` elsewhere); preflight reports a construction it answers false for as `MEMBER <class>.<init>` (`AlertDialog(context, 3)`). A local method may declare its result class with `returns(cls)` when its body does not make it evident (`AlertDialog.Builder.create`).

## Higher-level helpers

Typed Telegram operations (`telegram.*`, `menus.add`, `plugins.*`, `ui.layout_params`), the TL wire form and the reserved operation names are specified in `protocol-telegram.md`; the host declares none of them yet. `inspect_plugin_json` adds `sdk_requirements`, the host operations behind every SDK entry point the source references, and `preflight_plugin_json` reports each one the host does not declare as an `OPERATION` blocker whose detail is `<operation> (<SDK symbol or method()>)`.

`client.call`: `{name:str,args:[wireValue],kwargs:object}` → wireValue. Implemented Python entry helpers: get_last_fragment, get_messages_controller, get_user_config, get_connections_manager, get_send_messages_helper, get_media_data_controller, get_notification_center, get_account_instance, get_selected_account, send_message, edit_message, send_request, copy_to_clipboard (the route used by `android_utils.copy_to_clipboard`). ## Optional HTTPS requests subset

`requests.py` is bundled compatibility code, not upstream requests or a pip installation. It is deliberately NOT in SDK_MODULES: the host must advertise `requests` in capabilities.modules only when this file, Python ssl/socket/native dependencies and valid trust roots are actually packaged. On iOS the opener explicitly loads checksum-pinned packaged `certifi.where()` through `ssl.create_default_context(cafile=...)`; a missing/invalid trust store fails closed, without disabling verification. Other platforms use system default verification. This compatibility layer is not a network sandbox.

Supported: `request/get/post/put/patch/delete/head/options` at module and per-instance `Session` level, with headers and CookieJar, context manager/close; `get` accepts positional params, `post/put/patch` accept positional data, and `head` defaults to allow_redirects=False (explicit override supported); HTTPS-only absolute URLs without embedded userinfo; params, form/text/bytes data or JSON; headers; positive scalar timeout (default 15 seconds, maximum 60 seconds); allow_redirects bool; stream bool; verify=True. Response exposes status_code, content, text, json(), case-insensitive headers, url, ok, raise_for_status(), iter_content(), raw and close(). `requests.utils` holds `quote`, `unquote`, `urlparse` and `urlunparse`, which upstream re-exports from the standard library, and nothing else. urllib HTTP status errors become Response objects; only raise_for_status raises HTTPError for 4xx/5xx. Exceptions namespace includes RequestException, ConnectionError, Timeout, SSLError, HTTPError, InvalidURL, TooManyRedirects, ContentTooLarge, ContentDecodingError, UnsupportedOption, JSONDecodeError. Error messages omit URLs, response bodies and credential values.

Redirects resolve relative paths through urllib; HTTPS→HTTP/nonweb destinations are rejected. Authorization/Proxy-Authorization/Cookie headers are stripped when scheme/host/port origin changes. 307/308 preserve method/body; 301/302/303 use the explicitly implemented requests-style method change. Maximum redirects is five. Transport-controlled Host/Content-Length/Transfer-Encoding overrides are rejected. Bodies are fully buffered with limits of 8 MiB outbound and 16 MiB inbound/decompressed; gzip decoding is bounded, unsupported content encodings error. Accept-Encoding defaults to identity.

Streaming. With `stream=True` the body stays on the connection, which the response owns until it is read to the end or closed (`close()`, the context manager). `iter_content(chunk_size)` reads it in chunks of that size (65,536 bytes for `None`), bounded only by the socket timeout of each read, so a download is not limited to the buffering quota; `content` reads what is left and enforces the 16 MiB limit; a gzip body is decoded as it arrives. A read that fails mid-body raises `ConnectionError`, as upstream; iterating a body that was already consumed raises `StreamConsumedError`, and `content` after that `RuntimeError`. `raw` is the connection's undecoded stream (empty for a buffered response). On a buffered response `iter_content` slices `content`. `decode_unicode=True` and `iter_lines` are not implemented.

Not implemented: multipart/files, auth helpers, custom certificates/verify paths, proxies overrides, retries, per-connect/read tuple timeouts, hooks/adapters, arbitrary requests subpackages or asynchronous cancellation. The shim also checks a monotonic elapsed deadline between redirects and before/after bounded reads. A blocking socket read/open cannot be interrupted by these checks, so this is not a hard total wall timeout. urllib blocks the interpreter queue until completion; UI main must never wait for it. This only addresses a dependency import/API subset; other native adapters may be unavailable. SDK callback/load budgets count interpreter-thread CPU time via time.thread_time, so I/O waiting does not consume the 250 ms callback CPU budget. This does not add asynchronous execution or a native watchdog.

## Worker threads

`_ayu_host.dispatch` works only on the interpreter's dedicated thread, inside a native entry whose trusted owner is the calling plugin. Plugin code may still use `threading` (Thread, Timer, Lock/RLock, Event, Condition, Semaphore, `queue`) and `concurrent.futures.ThreadPoolExecutor`; `_ayu_threads` hooks `threading` once and is inert outside plugin code.

- A thread started while a plugin scope is current belongs to that generation. It starts with an empty context holding only that scope (Android threads do not inherit the caller's context variables either). Any other thread still gets `WRONG_QUEUE`, and a worker cannot use the queue-only entry points or another generation's scope.
- `Runtime.call`, `callback`, `schedule` and `register` made on a worker are executed whole on the queue thread, in the plugin's context, while the worker waits; results and exceptions are returned to it. Python callbacks never run on a worker unless plugin code calls them there. A call that is not served within 30 s raises `QUEUE_TIMEOUT`.
- The queue serves a generation's workers at every native entry of that plugin. A worker that queues a call asks for such an entry with `_ayu_host.wake` (see "Transport and ownership"), so an idle queue serves it as soon as the interpreter thread is free, not at the next timer. The fallback, for a host without `wake` or a full native queue, is one generation-owned `scheduler.schedule` pump (`pluginsQueue`) that exists only while the generation has live threads. Its interval is 10 % of the time since a worker last needed the queue, clamped to 10 ms–2 s; starting a thread, submitting to an executor or notifying a condition from the queue thread resets it. A host without `scheduler.schedule`/`scheduler.cancel` cannot serve workers, so thread imports and the thread-backed local classes stay blockers there.
- While the queue thread waits on `Thread.join`, a `Condition` (Event, Queue, Future, Semaphore) or a Lock/RLock created by plugin code, it keeps serving that plugin's workers, so it cannot deadlock against a worker that is calling the bridge. C-level waits (`time.sleep`, sockets, `queue.SimpleQueue`) are not served; workers then wait until the queue returns.
- Bounds: 64 live threads per generation and 256 in the interpreter, 1024 pending tasks per executor, looper or host queue; exceeding them raises `RESOURCE_LIMIT`. Worker threads are outside the cooperative `sys.settrace` budget; queue time spent serving them counts against the entry that serves them.
- Unload sets `BasePlugin.stop_event` before `on_plugin_unload`, which may join its threads. After deactivation every pending and later bridge call of the generation's threads raises `PLUGIN_UNLOADED`, its executors, loopers and timers are shut down, and a reload starts with no threads. Python cannot kill a thread: one that ignores the stop event runs until its function returns, without bridge access, and keeps counting against the interpreter-wide cap.
- An uncaught exception in a plugin thread is not printed; the host log receives `Uncaught <ExceptionType> in plugin thread <name>` only.

`_ayu_javalib/concurrency.py` provides `java.lang.Thread`/`Runnable`/`ThreadLocal`, `java.util.Timer`/`TimerTask`, the `java.util.concurrent` executors, futures, `CountDownLatch`, `Semaphore`, `TimeUnit`, queues, maps, `atomic.*` and `locks.*`, `android.os.Looper`/`Handler`/`HandlerThread`/`Message`/`CountDownTimer`/`AsyncTask`/`Process` and `org.telegram.messenger.DispatchQueue`. The main looper is the serial Python queue: `Looper.myLooper() is Looper.getMainLooper()` there and nowhere else, a worker has no looper until `Looper.prepare()`, and `Handler(Looper.getMainLooper())` posts with `scheduler.schedule` on queue `main` in milliseconds (negative delays become 0); `removeCallbacks` cancels every pending post of an equal runnable with `scheduler.cancel`. The local `android.os.Handler` overrides the host adapter. `Looper.loop()` on the queue thread, `postAtFrontOfQueue` on the main looper, `postAtTime`, `Message` bundles, thread factories and `Process.killProcess`/`sendSignal` raise `UNSUPPORTED_API`. Thread priorities (`Thread.setPriority`, `Process.setThreadPriority`) are recorded hints with no scheduling effect. `Thread.interrupt` wakes only the blocking methods of these classes. Idle pool workers exit after 30 s and are restarted on demand.

## Settings rows, dialogs and storage

`serialize_settings` and every `create_sub_fragment` callback return rows read as the Android host reads them (`ui.settings.android_rows`): a row is any object with the Android row attributes, `None` or an empty sequence means no settings, texts are `str()` of the attribute, a switch default is its truthiness, and a row Android would drop (no `type`, or a required field missing) is dropped. At most 256 rows per page. Wire types stay `Header|Divider|Text|Input|Switch|Selector`; `red` is sent as `destructive`. Descriptors may additionally carry `icon` (string), `on_long_click` (callback, one view argument) and `link_alias` (string) on Text/Input/Switch/Selector rows, and an Android `EditText` row is sent as `Input` with `hint`, `multiline` and `max_length` (always Android's default 256). The native settings screen currently draws no icon and delivers no long click; it resolves a link alias only when a plugin opens the screen through `plugins.settings` (`protocol-telegram.md`); a multiline `Input` is shown as unsupported. An `EditText` with a `mask` or another `max_length` raises `UNSUPPORTED_API`, because the native row applies neither. `Custom` rows and `SimpleSettingFactory` raise `UNSUPPORTED_API`. Row callbacks of a sub-fragment page stay registered for the eight most recently opened pages; older pages answer `CALLBACK_EXPIRED`.

`AlertDialogBuilder` always sends an `on_click` callback for each button and for `items`, so the SDK learns that the dialog closed and releases its callbacks. `set_view` forwards an unparented host view as `view`. `cancelable` is sent as `false` when either Android switch (`set_cancelable`, `set_canceled_on_touch_outside`) was turned off on a created dialog. Dismiss listeners run after a reported click or `dismiss()`. The host sends no callback when the user closes a dialog another way (its own Cancel button on a cancelable alert without a negative button, a tap outside a custom-view dialog); the SDK therefore calls the owned dialog's `isShowing` before it relies on a dialog being on screen (`show`, setters, `AlertDialog.isShowing`), and on `false` releases the callbacks and runs the dismiss listener then, not earlier. `show` on a dialog that is on screen does nothing, as on Android; `show` after any dismissal presents the dialog again with new callbacks. Dim, blur, button colour keys and resource providers have no effect. `make_button_red` is a visual degradation: the alert operation has no destructive-button field, so the button keeps its default colour, the dialog otherwise works, and the SDK logs this once per plugin generation (a non-int button id still raises `TypeError`). Cancel and back-button listeners, progress styles, item icons, top images/animations and clickable message links raise `UNSUPPORTED_API`.

`org.telegram.ui.ActionBar.AlertDialog` is a Python-local class over this builder wherever the host declares `ui.present` (it overrides the host adapter, whose instances stay the references `ui.present` returns; without the operation its members are `OPERATION` blockers). `AlertDialog.Builder(context[, [progressViewStyle,] resourcesProvider])` chains Android's setters (`setTitle`, `setMessage`, `setPositiveButton`/`setNegativeButton`/`setNeutralButton`/`setButton`, `setItems`, `setView`, `setOnDismissListener`, `setOnPreDismissListener`, `makeRed`, the dim, blur and colour-key hints) into the dialog `create()` and `show()` return; `AlertDialog(context, progressStyle[, resourcesProvider])` takes the same setters directly, with `show`, `dismiss`, `cancel`, `isShowing`, `setCancelable` and `setCanceledOnTouchOutside`. A listener is an implementation of the interface (`AlertDialog.OnButtonClickListener`, `DialogInterface.OnClickListener`, `OnDismissListener`) or a callable and receives the dialog, then `which` (-1, -2, -3 or the item index); the pre-dismiss listener runs before the dismiss listener. A button without a text is not shown. The refusals above apply unchanged, and the Java members that would need them are not defined at all (`setOnCancelListener`, `setOnBackButtonListener`, `setTopImage`, `getButton`, `getWindow`, `setOnShowListener`), so preflight reports them as `MEMBER`. Layout hints the system alert cannot render (`setCustomViewOffset`, `forceVerticalButtons`, `setWidth`, `makeCustomMaxHeight`, `setDimAlpha`) are accepted and logged once per plugin generation. Progress dialogs have no presentation: `ui.present` requires a button and has no spinner or progress kind, so `ALERT_TYPE_LOADING`/`ALERT_TYPE_SPINNER` raise, a literal progress style in `AlertDialog(...)` or `AlertDialog.Builder(...)` is `MEMBER <class>.<init>`, and a reference to `AlertDialogBuilder.ALERT_TYPE_LOADING`/`ALERT_TYPE_SPINNER` is an `OPERATION` blocker under `sdk.unprovided_member`.

`BulletinHelper.show_undo` is a bulletin with an `Undo` button plus one `scheduler.schedule` job on queue `main` (5000 ms) that runs the action unless undo was pressed.

`file_utils.get_plugins_dir`, `get_cache_dir`, `get_files_dir`, `get_images_dir`, `get_videos_dir`, `get_audios_dir` and `get_documents_dir` create and return directories of the application container, found through `HOME`: `Library/Application Support/AyuPluginFiles/<plugins|files|images|videos|audios|documents>` and `Library/Caches/AyuPluginFiles`. They are shared by all plugins, hold nothing Telegram downloaded, and are not removed when a plugin is deleted. Without a container directory the helpers raise `UNSUPPORTED_API`.

A `.plugin` loaded under a relative `filename` runs with `__file__`, its code objects' filename and tracebacks set to `<plugins dir>/<basename>`, the place the file has on Android, so paths built next to `__file__` are writable. The path is computed from `HOME` only: loading creates no file or directory and stores no source there, and without a container directory the name stays as given. An absolute `filename` is kept.

## Plugin packages (`.elyx`, `.eaf`)

A package is a ZIP archive read as Android's `elyxcore` reads it: `refmap.{yaml,yml,json}` names `main`, `metainfo`, `assets`, `strings` and `wheels`; without a refmap the root `metainfo.*`, `main.py`, `assets/` and `strings/` are used. Manifests and string tables are JSON or a bounded YAML subset (`_ayu_yaml`: block and flow collections, plain/quoted/block scalars, PyYAML 1.1 scalar typing; anchors, tags, complex keys and multiple documents are errors).

Native side: `APBPythonRuntime` has `inspectPackage`, `preflightPackage` and `loadPackage(path:filename:completion:)`, which run on the interpreter thread exactly as the source entry points do (`$inspection` owner for inspection, one admitted job that inspects and then loads under the package's own id, the same queue budget and error codes; an invalid path is the source error 3). `AyuPluginService` accepts `.plugin`, `.elyx` and `.eaf`: a selected archive of at most 64 MiB is streamed into `AyuPlugins/Staging`, hashed and preflighted there, and that same file is moved to `AyuPlugins/<id>.<elyx|eaf>` beside the record's JSON (`packageExtension`); nothing is unpacked or executed. Blockers are shown as for a `.plugin`. Every enable hashes and preflights the stored archive again before `load_package`. Deleting the plugin removes the archive, the record, the settings namespace and `<plugins dir>/ElyxPlugins/<id>`; an update replaces whichever stored form the plugin had and keeps the previous one if a write fails. Restoring installed records never starts Python.

Entry points take the path of the stored archive, never its bytes:

- `inspect_package_json(path, filename="plugin.elyx") -> str` and `preflight_package_json(path, filename) -> str`: the plugin report shape (`metadata` mapped to the `__id__`… keys, `imports`, `classes`, `requirements`, `warnings`, `unsupported_sdk_symbols`, `imported_symbols`, `unsupported_imports`) plus `package: true`, `main`, `refmap`, `modules`, `entries`, `unpacked_bytes`, `sdk_requirements`, `package_findings` and, for preflight, `blockers`. `sdk_requirements` is collected over all modules as for a `.plugin` and yields the same `OPERATION` blockers; a method name counts as the package's own when any of its modules defines a function of that name. Every `.py` module outside the assets/wheels directories and dot-directories is inventoried; imports that resolve to the package's own modules (below the package root as Android resolves them, or beside the importing file) are not dependencies. `elyx` names are checked against the public `elyxcore` API plus `settings`, `refmap`, `metainfo` and, when the package has them, `assets` and `strings`. Additional blocker code `PACKAGE`: `compiled Python bytecode`, `bundled wheels`, `required plugin <id>` (only the built-in `zwylib` satisfies a `requires` entry). Nothing is authorized, unpacked or executed.
- `load_package(path, filename="plugin.elyx", expected_id=None) -> dict`: repeats the analysis, rejects any blocker with `LOAD_REJECTED`, then follows `load_plugin`: `plugin.authorize`, `plugin.activate`, execution, `on_plugin_load`. The archive is unpacked to `<plugins dir>/ElyxPlugins/<id>/`: each entry is streamed in 64 KiB pieces into a new `<name>.ayu-unpack` file (`O_EXCL | O_NOFOLLOW`) that is renamed into place, and a link or directory where a package file, its temporary file or a package directory belongs is `LOAD_REJECTED`, module source is executed from the inspected archive bytes under `ElyxPlugins.<id>.<module>` with real `__file__` paths, and the first `BasePlugin` subclass in the main module is instantiated. `unload_plugin` removes the generation's modules, including ones imported from its unpacked directory, and its `sys.path` entries. The unpacked files stay on disk.

Archive bounds: 64 MiB file, 4096 entries, 256 MiB unpacked, 32 MiB per entry, 4 MiB per Python module, 1 MiB per manifest or string table, 1024 modules, 512-byte entry names, depth 32. Encrypted entries, symbolic links, absolute or `..` paths, names ending in `.ayu-unpack`, backslashes, duplicate (case-folded) names and compression other than stored/deflate are `LOAD_REJECTED`. The cooperative load budget counts lines of every module below the package directory.

## Limits and validation

The source limit is **4 MiB UTF-8**, aligned across the installer, Objective-C load/preflight and Python inspection. Wire request/response limits remain independently bounded; AST depth/node quotas still apply even within the byte limit.

Wire bounds, enforced with the same numbers on both sides (`ayu_bridge.MAX_*`, `AyuPluginBridgeLimits`, `APBPythonRuntimeQueueBudget.h`; `Tests/Python/test_queue_transport.py` compares them):

| Envelope | Bound | Past it |
|---|---|---|
| Dispatch request | 262,144 bytes of JSON; 1,572,864 for `telegram.*` operations | `RESOURCE_LIMIT`, raised by the SDK before the host is called |
| Dispatch result | 262,144 bytes; 1,048,576 for `telegram.*` operations | `resource_limit` |
| Callback or event JSON read by the SDK | 6,000,000 characters | `PROTOCOL_ERROR` |
| Callback arguments from the host | 262,144 bytes; 5,900,000 for a `telegram.request` callback and for hook callbacks | see "Delivery queue" and `protocol-telegram.md` |
| Callback result | 1,048,576 bytes of JSON | `RESOURCE_LIMIT`; the callback counts as failed |

The interpreter queue (`ObjC/APBPythonRuntimeQueueBudget.h`) holds at most 64 jobs and 32 MiB. A queued job is charged its input (four bytes per UTF-16 unit); only the job that is executing also reserves the 7 MiB a maximum result can occupy, and a finished job keeps its input and its actual result charged until its completion has returned on main. Admission always leaves room for one such reservation, so every admitted job can run; when undelivered results leave none, the interpreter thread waits for main to take them. A job that does not fit is refused with code 4 and the runtime tells its client when room returns.

Python bounds: source 4 MiB UTF-8, JSON input 6 million characters, nesting 64, 32 loaded scopes, 4096 callbacks and 1024 registrations per plugin. Native host must separately bound its handles/queues and preserve signed Int64 values. A cooperative `sys.settrace` CPU-time budget uses `time.thread_time` and checks every 64 original-source line events: load 2 CPU seconds, callback/event 250 CPU ms, settings/unload 500 CPU ms. The previous trace is restored. Elapsed wall time and I/O waits are not the budget. This interrupts ordinary Python loops but is catchable and cannot interrupt blocking native/stdlib calls; it is not a hostile-code watchdog or sandbox, and no native watchdog is implemented by this SDK.

No upstream requests/pip installation, Android emulator, arbitrary Java class/member, arbitrary Swift selector, Python native extension loader, unrestricted method hooking, Android Canvas renderer, or full Android layout engine is supplied in these Python files. The optional requests facade above is only its documented subset. Host capabilities must advertise only adapters really implemented. A plugin may pass static inspection and later request a dynamically computed unsupported API: it must then receive an explicit failure. Static inspection is a preflight, not proof of full compatibility or a security sandbox.

Tests in Tests/Python use a fake injected host, test-authored synthetic source and offline source/hash fixtures only. They cover owner isolation, response validation, generation-bound lifecycle events, remote reference round trips, callback lifetime, unload cleanup, enums, undeclared classes and pre-execution rejection. HTTPS fixtures use a fake urllib opener and fake clock; no live service is contacted. No supplied plugin is executed. Offline source wiring and hash checks do not execute Swift, establish native UI behavior or verify device startup. Native integration still requires the authorized iOS test environment and real device/recorded-frame verification.
