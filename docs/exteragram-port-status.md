# exteraGram non-plugin port inventory and gap audit

**Current integration state:** see [exteragram-implementation-status.md](exteragram-implementation-status.md).
The detailed tables below are the initial source inventory; subsequent implementation
addresses some listed gaps. They are retained as the Android scope checklist, not as
the final verification report.

The current integration document records reachable additions for custom AI, local
channel feed, conversions, advanced lyrics, HTTP pills, sticker size/shape/time modes,
Photo Tools, browser subscriptions and cloud-chat takeout. The original gap rows below
are historical inventory and must not override those newer implementation notes.
Full Android parity, Swift compilation and recorded iOS acceptance remain unconfirmed.

Audit date: 2026-11-25. This is a source audit, not a declaration of feature parity or a runtime acceptance report. The iOS reference is fetched `origin/master` at `718cc4ddd53446835d066ac658b4f76d16358b9e` **plus the ongoing worktree additions**. The checkout initially remained at older `d103a23c`; that older checkout is not the parity baseline. Master files were inspected with `git show`/`git grep origin/master`; added settings and changed consumers were read from the worktree. These two layers were being integrated concurrently, so this document credits their union while explicitly flagging duplicate settings and unresolved wiring. Other agents may change it further; a final integration pass is required.

Android reference: [exteraSquad/exteraGram at b4d852f48f2734a0bee1a74a0939be621612262a](https://github.com/exteraSquad/exteraGram/tree/b4d852f48f2734a0bee1a74a0939be621612262a), the SHA recorded in `.extera-scratch/tree.json`. The seven preference snapshots in `.extera-scratch` were read without editing them. `ExteraConfig.kt`, `AiConfig.kt`, and `AppNavigationPreferencesActivity.kt` were additionally inspected at that exact upstream revision. A repository tree establishes the existence and scope of a subsystem, but does not establish its exact behavior or its reachability in every Android build.

All plugins are excluded: no plugin engine, loader, SDK, Python environment, repositories, installation, updates, developer mode, hooks, or plugin preferences are port requirements in this document. Native non-plugin features remain in scope even if a shared Android preferences file imports plugin classes. This audit made no application-code changes.

## Reading the status

- **Wired**: an iOS setting or existing behavior and a consumer were identified. Compilation, runtime behavior, and exact Android parity are still unverified.
- **Partial**: an analogue exists, but options, scope, defaults, reachability, or behavior differ.
- **Gap**: no implementation/setting was found in the inspected iOS application domains. This is a search-backed finding, not proof that no differently named implementation exists anywhere in the repository.
- **Platform adaptation**: Android APIs or UI conventions need an explicit iOS design; this is not a claim that the user-visible capability can be omitted.
- **Unresolved**: source inventory found the subsystem, but consumer-level comparison is incomplete.

## Immediate integration findings

1. **Master already implements substantial General and Appearance scope.** Credit translation button/chat/provider/target/ignored-language controls; notification-delay, relative-last-seen, save-album, ID/DC and archive controls; hide action-bar status/compose/search, mini avatars, and folder title/counter modes. Do not report these as missing based on the older checkout. Evidence: `origin/master:Swiftgram/SGSettingsUI/Sources/SGSettingsController.swift`, `ExteraSettings.swift`, `ChatListController{,Node}.swift`, `Node/ChatListItem.swift`, `SaveToCameraRoll.swift`, `PresenceStrings.swift`, and `SharedNotificationManager.swift`.
2. **Concurrent additions must share one authoritative setting per feature.** Master stores relative last seen/archive/ID modes on `ExteraSettings`; new `ExteraGeneralSettings` introduces separate keys and changed consumers. Master also supplies translation target storage while additional translation settings are being built. The UI, backup, consumers and migration must agree after integration. Worktree category additions now expose Chats/Media/Other and message/reply/reaction controls, resolving the older checkout's empty Chats/search-only issue. Preserve master's General/Appearance entries when merging [SGSettingsController](../Swiftgram/SGSettingsUI/Sources/SGSettingsController.swift).
3. **Settings and defaults differ from Android.** Android defaults include `filterZalgo=true`, `replaceEditedWithIcon=true`, `hideShareButton=true`, `removeMessageTail=true`, `addCommaAfterMention=true`, `alwaysSendInHD=true`, and `showIdAndDc=1`. iOS stores retain false defaults for several of these; master uses `archiveOnPull=true` while Android uses false, and mini-avatar defaults differ. Preserve or deliberately migrate defaults; matching names alone are insufficient. Android evidence: [ExteraConfig][config]. iOS evidence: [ExteraSettings](../Swiftgram/SGSimpleSettings/Sources/ExteraSettings.swift), [SG defaults](../Swiftgram/SGSimpleSettings/Sources/SimpleSettings.swift#L281), and the new dedicated setting stores.
4. **Avatar geometry is an adaptation, not exact parity.** Android scales forum/community radii from the chosen radius and uses `ceil`; iOS uses a fixed quarter-diameter radius for forums when the single-radius option is off and `floor` elsewhere, with no community argument. Evidence: `getAvatarCorners` in [ExteraConfig][config] and [iOS geometry](../Swiftgram/SGSimpleSettings/Sources/ExteraSettings.swift#L97).
5. **Existing exports and feeds must not be counted as complete.** iOS JSON export scans locally stored cloud messages and emits basic fields; it is not Android's account takeout pipeline. iOS News code exists but is explicitly disabled while its API is unavailable, including its device-built Added feed. See the larger-domain table below.

## Validation limits and acceptance work

This document was produced on Windows. Xcode, Apple SDK compilation, Bazel iOS linking, iOS unit-test runners, simulator interaction, real accounts, hardware cameras, notification delivery, provider networking, wallet operations and export round-trips were not available or were not run. No Android app was built or driven. No claim above means a feature was exercised. Repository `AGENTS.md` requires frame-labelled simulator recordings for visual and animated changes; there are no such recordings from this audit.

Negative searches used relevant identifiers and paths across tracked Swift/Objective-C application sources and inspected settings consumers. They exclude claims based solely on generated API types, bundled asset names, Watch models, or low-level primitives. Because Android modifies upstream `org/telegram/` code and native libraries as well as `com/exteragram/`, the custom-package tree plus settings cannot enumerate every behavioral difference. A complete port still requires a pinned upstream diff/call-site audit, particularly `ChatActivity`, message cells, media viewer/player, launch/settings/profile screens, network/download/upload, wallet and web browser.

Acceptance should cover: every non-plugin setting is reachable without search; persistence survives restart and updates active consumers; enum choices/defaults migrate deliberately; native iOS equivalents are explicitly documented; app-group settings reach extensions; behavior works across accounts and all composer/history/media backends; server/provider errors and cancellation terminate correctly; and visual work has recorded-frame evidence. Tests must exercise behavior rather than merely count enum cases or settings rows. A full iOS build and relevant existing test targets remain necessary after implementation.

No plugins were added or modified. The pre-existing user edit to `.extera-scratch/bracket_check.py` was left untouched. No commits were created by this audit.
